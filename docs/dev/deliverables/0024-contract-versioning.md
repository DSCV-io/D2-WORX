# Deliverable 0024 — Contract & API versioning strategy (implementation)

**Status:** SHIPPED 2026-06-26 — converged + CI-enforced on branch. **Branch:** `n/contract-versioning` (off clean `nova`). **Implements:** [ADR-0024](../adrs/0024-contract-api-versioning-strategy.md) (amended at ship for the artifact-diff + source-based-fingerprint + multi-major-one-instance models).

## Goal

Turn the contract side of ADR-0024 from a documented strategy into enforcing machinery. Before this deliverable the proto emitter assigned field numbers positionally (a reorder or insert silently renumbered the wire; a delete freed a number for silent reuse) and nothing in CI blocked an accidental wire break — so a breaking-change gate would have been theater. This deliverable builds the pieces that make the wire honest and the gate meaningful: author-pinned proto field numbers plus `reserved` emission; `@typespec/versioning` adoption with the `v2alpha → v2beta → v2` stability-channel naming and the real `d2.keycustodian.v1 → d2.keycustodian.v2alpha` renumber; an always-on strict breaking-change gate wired into CI; the Tolerant Reader proven by test on the generated consumers; per-package semver + CHANGELOGs with a footer-keyed release runner; and an artifact-diff versioning engine that derives each package's bump from what actually changed in its published surface. The two runtime pieces that need a running Edge request pipeline (the `Deprecation` / `Sunset` response middleware and telemetry-gated removal) are Edge-host-gated and carry a permanent tracking row in `docs/v2/POST_PIVOT_ROADMAP.md`.

## What shipped

- **Author-pinned proto fields + reserved emission (`@d2Field` / `@d2Reserved`).** A `@d2Field(n)` decorator pins each proto field number on the model property; a model-level `@d2Reserved` list emits `reserved N to M;` / `reserved "name";` lines. The proto emitter stopped its positional `fieldNumber++` counter and now honors the author pin, failing loud (a `D2TSP*` diagnostic, no partial file) when a proto-bound model carries an unpinned field. Reorder-immunity and delete-safety are now properties of the wire, not of authoring discipline. The introduction was byte-neutral by construction — the initial pins reproduce the prior positional numbers.
- **`@typespec/versioning` adoption + wire-identity derivation.** The live `D2.KeyCustodian` namespace is `@versioned` via a `Versions` enum; the channel/generation segment (`V2Alpha` / `V2Beta` / `V2`) is derived so the C# wire namespace, the TS package name, and the proto package agree by construction, with a cross-validation diagnostic (`D2TSP010`) that fires loud on any segment mismatch. The committed `d2.keycustodian.v1` was genuinely renumbered to `d2.keycustodian.v2alpha` across the proto package literal, the C# proto namespace, the fixtures, and every byte-gate test literal. A `wireVersion` constant carries the channel string for a day-one handshake.
- **Always-on breaking-change gate (`tools/contract-gate`).** Three diff arms against the baseline branch — `buf breaking` over proto, a hand-rolled JSON-diff over `*.spec.json` catalogs + i18n keys, and an OpenAPI-diff over the committed `*.openapi.g.json` documents — plus a shared per-break force valve (the `WIRE-BREAKING:` / `BREAKING CHANGE:` footer parser, the same module the release runner consumes so the valve signal and the bump signal cannot diverge). Pre-stable `0.x` channels break freely; only stable `vN` is gated, and the gate is proven non-vacuous against a synthetic stable-break fixture. Deprecate-not-delete is enforced: a spec entry going away gets a `deprecated` marker (→ `[Obsolete]` / `@deprecated`) and deletion of even a deprecated entry is a break.
- **Tolerant Reader as a tested property.** Adversarial tests assert that every generated consumer surface (C# proto mapper, C# JSON envelope, TS proto decode, TS REST JSON) ignores an unknown extra field rather than throwing, plus a forward-compat case where a v1-shaped reader reads a v2-shaped payload — the additive-is-free property the whole strategy rests on, pinned by test.
- **Per-package semver + CHANGELOGs + the footer-keyed release runner.** All 83 consumable packages (54 .NET `D2.Shared.*` incl. the KeyCustodian client + 29 TS `@d2/*`) were seeded publish-ready at `0.1.0` with CHANGELOG skeletons and publish metadata; `tools/release-runner` is an owned ESM/vitest tool that bumps per package, prepends a changelog block, and graduates `0.x → 1.0.0`, attributing commits to packages by file-path containment. A manual `release-libs.yml` `workflow_dispatch` cuts a GitHub Release as an atomic all-libs bundle; registry publishing is never automatic. A commit-message lint (`tools/commit-lint`) enforces the conventional-commit type set.
- **Artifact-diff versioning engine (the bump source of truth).** The per-package bump is derived from the actual published-artifact diff, not the commit-type label: output changed → at least PATCH; public API added → at least MINOR; public API removed / broken → MAJOR (MINOR while pre-stable). The public-API surface is captured by committed baselines — .NET via PublicApiAnalyzers (`PublicAPI.Shipped/Unshipped.txt`), TS via api-extractor (`etc/<pkg>.api.md`). The output fingerprint is a **source-based portable** SHA-256 over committed source + the API report + resolved dependency versions + a declared toolchain pin, computed with `git ls-files` (committed-only) so it is byte-identical on any OS and reproducible by any contributor. Propagation falls out of the manifest fingerprint — a dependency bump changes a dependent's manifest, so its fingerprint moves and it PATCH-bumps. A git-ref text diff of the committed API reports is the apiDiff; a drift-check + a `versioning-integration` CI lane recompute the baselines on Linux and assert zero drift. The commit footer is demoted to an escalation override that can only raise the diff-derived floor.

## Key architectural decisions

- **Artifact-diff bump is the default; the commit footer is escalation-only.** The earlier commit-type→bump model was a footgun — a `chore` / `build` / `refactor` change to shipped code stranded the package at no bump, so it never published and consumers went stale, and authors had to mislabel commits to force a release. Deriving the bump from what actually changed in the published output removes both. The legacy commit-type path survives one cycle behind `--legacy-commit-type` as an escape hatch.
- **Source-based portable fingerprint, chosen after a cross-platform drift discovery.** The first fingerprint hashed built output (an IL dump of the freshly built DLL; a hash of the freshly built `dist/`). That is not byte-stable between the Windows machine that seeds the baselines and the Linux CI that recomputes them, so the engine would have floored every package at PATCH every release and the drift lane would have false-failed on day one. The fix was to hash committed source + the API report + resolved deps + a toolchain pin instead — portable by construction, no CI-only re-seed, dropping the custom IL-dump tool entirely. A separate one-line POSIX path bug (a `.csproj` `ProjectReference` with backslashes silently dropping deps on Linux) was the last divergence to close.
- **Propagation via the manifest fingerprint.** Because resolved dependency versions are part of the fingerprint input, a dependency bump changes a dependent's fingerprint automatically — propagation is derived, not a separate breadth-first traversal kept in sync by hand. The dependency-graph code is retained only for topological ordering.
- **Registry publishing is never automatic.** Packaging is proven publish-ready (a valid `.nupkg` / tarball, a pack smoke test in CI) but the actual push to npm / NuGet stays a deliberate manual step, credential-gated and tracked, not wired.
- **Multi-major serving is one service instance.** Coexisting wire majors are served by the same running service with one semver, one DB, one migration set; older generations are translation shims to the latest internal model, never a fork of the domain or deployment. (Amended into ADR-0024.)

## Kinds-of-misses log (evidence behind the rule additions)

- **String-literal line length over-flagged as a violation.** Several FINAL-REVIEW rounds repeatedly flagged test-description strings and diagnostic-message templates that ran past 100 chars. They were settled as a non-enforced over-flag: 60+ such instances already live in-tree (test descriptions + message templates) and pass both Prettier and the build, because Prettier does not break a single string literal's content and breaking one into a concatenation hurts readability and grep/searchability. The line-length rule governs code structure, not literal content. → §7.14 amended with the string-literal exemption.
- **Fixer-output hygiene recurred and cost extra rounds, two classes.** Across the deliverable's fix cycles a Fixer left a finding-/round-ID in a comment it authored while fixing an unrelated item, and a separate Fixer added a regression test without updating the VALIDATION-ledger test-count. Both slip the closure-by-absence model — neither was present in the prior sweep's surface, so each appears NEW only on the next full round. → a new predicate naming both as a pre-return self-check.
- **Cross-platform fingerprint drift was invisible to same-OS testing.** Every same-OS path-independence proof passed; the Windows-seed → Linux-recompute divergence (built-output non-determinism, then a POSIX project-reference path bug) only surfaced when the CI lane first actually ran on Linux. The lesson — a portable artifact identity must be proven across the real seed→recompute OS boundary, not just same-OS — is reflected in the source-based-fingerprint redesign and the required drift lane.
