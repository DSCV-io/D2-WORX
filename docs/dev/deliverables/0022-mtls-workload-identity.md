# Deliverable 0022 — mTLS workload identity (dev-first) + forwarded-token shape

**Status:** SHIPPED 2026-06-19 — converged + governed. **Branch:** `n/auth-pivot` (continuation of the 0021 auth-pivot docs branch; base `f7810a0f`), merges back into `n/typespec-emitters` after SHIP. **Predecessor:** 0021-auth-pivot (the decision-record docs); this deliverable IMPLEMENTS ADR-0022 (mint-once-forward) + ADR-0023 (mTLS workload identity).

## Goal

Build the **dev-first internal-mTLS workload-identity layer** and pin the **forwarded transaction-token shape**, so cross-process gRPC hops authenticate the *peer workload* (mTLS, additive) independently of the *forwarded user/authz token* (mint-once-at-Edge). mTLS is **additive — never a reason to skip token validation** (the ADR-0007 invariant). KeyCustodian becomes the internal CA.

**End state shipped:** the reusable mTLS plumbing — CA issuance (KeyCustodian as a fully-governed internal CA) + server require-and-validate + client leaf/chain presentation + SPIFFE-SAN peer validator — exists, is adversarially tested, and is **proven end-to-end over the real `Signer.Sign` gRPC hop** on a real Kestrel-on-loopback handshake (valid leaf connects; no-leaf / wrong-CA / expired / foreign-SAN / unknown-workload all rejected at the handshake). Wiring mTLS into a *running Edge gRPC host* is genuinely deferred (Edge `api/` is `.gitkeep` — no host exists yet) with an explicit, tracked to-be-done note.

## Locked decisions

| ID | Decision | Detail |
| -- | -------- | ------ |
| D1 | **CA hierarchy = root + issuing intermediate.** | Root offline in prod (in `secrets/` in dev); intermediate online in KeyCustodian, signs leaves. Prod hardening = move the root key offline, no code change. |
| D2 | **Workload identity = SPIFFE-style SAN URI** `spiffe://d2.internal/workload/<service>`. | Peer check = trust-domain `d2.internal` (grammar-fixed) + workload ∈ the receiving host's allowed set. An on-ramp to a future SPIRE/Istio adoption. |
| D3 | **Short-lived leaves + refresh-ahead; expiry-first revocation.** | Short-lived leaves (~24h dev, configurable) + proactive refresh-ahead reusing the internal-token refresh-ahead pattern. CA long-lived under KeyCustodian's overlap rotation. Short-TTL expiry is the primary revocation mechanism + `CompromiseKey` to stop reissue / roll the CA; no CRL/OCSP in v1 (documented as future — the SPIFFE "expire, don't revoke" posture). |
| D4 | **ECDSA P-256 / SHA-256** for root + intermediate + leaf. | Research-led (NIST SP 800-57: P-256 ≡ RSA-3072 ≡ 128-bit; OWASP Crypto-Storage ECC-first; SPIRE's X.509-SVID default). Internal-only PKI → no RSA-compat need; short-lived rotating leaves favor ECDSA's faster keygen/handshake. |
| D5 | **KeyCustodian-as-internal-CA via a managed `X509CaCertificate` key.** | CA (root + intermediate) = full `EncryptionKey` sum-type aggregates (reuse lifecycle + overlap rotation + audit); leaves = on-demand, non-persisted issuance records returned by `IssueWorkloadCertificate`. Add `KeyType.X509CaCertificate` (CA only — no leaf KeyType); the `EnsureMaterialShape` public-material invariant gains the CA case. Dev CA bootstrap = `gen-dev-keys.sh` emits root + intermediate (openssl, PEM + PKCS#8) into `secrets/`; `FileCaProvider`/`ICaProvider` load + chain-validate (fail-loud); a `CaSeedingService` seeds them into the DB as managed CA keys. |
| D6 | **.NET mechanism = no new host framework.** | Server: Kestrel `ClientCertificateMode.RequireCertificate` + custom SPIFFE-SAN validation — server *logic* in `D2.Shared.AspNetCore`, *composed* by `D2.Shared.ServiceDefaults` (reconciles ADR-0023's "via service-defaults" with the service-defaults zero-logic aggregator law). Client: leaf/chain presentation + refresh-ahead via the outbound gRPC builder + `SocketsHttpHandler.SslOptions`. |
| D7 | **Build scope = plumbing + harness proof.** | The reusable plumbing + an end-to-end proof on the `Signer.Sign` harness. Edge-host wiring + the cross-process gRPC issuance contract are genuinely deferred (Phase-3-gated; no Edge host, no gRPC issuance API, unsolved first-leaf bootstrap). Tracked, not silent. |
| D8 | **Internal audience = a special-case `D2InternalAudience` code constant.** | Hand-declared in `D2.Shared.Auth.Abstractions` (the universal *receive* audience every hop validates; never a token-exchange target — so NOT in `audiences.spec.json`, whose entries are exchange targets). A protocol constant, not a spec-mirror DTO — no codegen-discipline violation. The future Edge minter + every per-hop validator reference the constant, never a raw `d2.internal` literal. |

## Cross-cutting decisions

- **mTLS is additive, never a validation-skip** (the ADR-0007 invariant). Every test + the design doc reinforces that the peer-cert check does NOT gate or replace token validation — both run. Enforced at three levels (design doc, validator, harness).
- **Fail-loud, not fail-open.** Missing CA, invalid chain, unknown-workload SAN, expired leaf → hard reject. No silent fallback to plaintext or skip-validation; the validator is default-deny.
- **A missing/unloadable mTLS CA degrades, it does not crash.** KeyCustodian is a module within Edge; an absent mTLS CA must not take down Edge's other functions. The CA provider returns a typed `D2Result` failure (not a swallowed exception), the seeder logs an explicit warning and continues, and mTLS issuance returns the `NoActiveIssuingCa` 503 until the CA is seeded — an HONEST degrade.
- **No payware, no vendored CA.** `System.Security.Cryptography.X509Certificates` (BCL) + `openssl` (dev bootstrap) only. Runs locally.
- **Reuse over invent.** Refresh-ahead, overlap rotation + the sum-type lifecycle + audit (KeyCustodian), service-defaults host composition, the outbound gRPC builder. Net-new code only where genuinely net-new (the cert primitives + the SPIFFE SAN + the CA provider).

## Resolved design questions (S1)

The three open design points + the S1 Planner's open questions, resolved with codebase grounding:

- **Audience model** → the special-case `D2InternalAudience` constant (D8) — semantically the universal receive audience every hop validates, consistent with the existing `d2-edge` special-case, and NOT a spec-mirror DTO.
- **Cert key algorithm** → ECDSA P-256 + SHA-256 (D4), research-led (NIST / OWASP / SPIRE).
- **Leaf modeling** → CA (root + intermediate) = full `EncryptionKey` aggregates (reuse the lifecycle + overlap rotation); leaves = on-demand, non-persisted issuance records.
- **`KeyType`** → add `X509CaCertificate` (CA only); no leaf KeyType. The `EnsureMaterialShape` public-material invariant gains the CA case (the CA carries public cert material).
- **CA-cert storage** → a dedicated certificate-material column/VO, NOT reusing the JWKS-scoped `PublicKeyMaterial` (whose invariant is bound to "the public key that feeds JWKS").
- **Leaf-issuance audit** → persist a lightweight issuance audit entry (which workload, when, which issuing CA) — a dedicated `LeafIssuanceAuditRecord`, not the kid-FK lifecycle-action `KeyAuditRecord`.

## Kinds-of-misses log (evidence behind the candidate rules)

- **M1 — A new readability convention surfaced its own StyleCop interaction (S2/S3, then S4).** The blank-line-around-`if`/loop + multi-line-statement convention (formalized this deliverable as the §5.8a predicate) has a SA1510 caveat: a blank line is prohibited BEFORE a `catch` / `finally` / `else` / `do-while` continuation. The S4 audit caught post-rule misses (8 §5.8a sites + 3 catch-after-try) — the rule's own first application needed the caveat documented so an Implementer does not add an illegal pre-`catch` blank. → candidate §5.8a refinement.
- **M2 — A step that changes spec-declared codes/locks/keys must run the SHARED test project (S2/S3).** S2/S3 added 3 KeyCustodian error codes, which regenerated the SHARED merged `ErrorCodeRegistry`; the Implementers ran only the Edge filter and missed the `D2.Shared.Tests` `ErrorCodeRegistryTests` count pin (41, stale → broke). Fixed the pin (41→44) + the completeness check. → candidate rule: a step touching spec-declared codes / advisory-locks / TK that regenerate a shared cross-service registry MUST run the shared (or full-solution) test project, not just the service filter.
- **M3 — A sub-agent diagnostic that mutates machine/OS state causes a false-green (S5).** An S5 Fixer reported the real-socket harness 825/825 green; the orchestrator's independent clean re-run found it failing 7/7 — the Fixer's diagnostic had installed the test CA root into the Windows cert store (`CurrentUser\Root`), so the server could start only on that polluted machine. The user independently confirmed they saw the diagnostic's root-install popups. → candidate rule: the orchestrator MUST verify a "green" on a clean state; a sub-agent's gate claim is not trusted when its work could have mutated machine/OS state.
- **M4 — A platform-incompatible real-socket transport test runs in the deploy-target container, not raw on the dev host (S5).** Clean-Windows real-socket mTLS with a private CA was empirically PROVEN intractable — Schannel's `SslStreamCertificateContext.Create` throws for ANY non-OS-trusted-root chain (server and client cert; MS-documented: "add the certificates to the certificate store manually"). The resolution: run the real-socket E2E as a committed one-command Docker/Linux test (the actual deploy environment), `SkipWhen(IsWindows)` on the 6 cert-presenting cases (honest skips), a `RequireCertificate` no-cert canary on EVERY platform, and the validator's full conjunct matrix proven cross-platform by in-memory unit tests. → candidate rule: a transport test that cannot run on the dev OS runs in the deploy-target container with an honest skip + a cross-platform unit matrix + a same-platform canary — never silently deleted, never faked green.
