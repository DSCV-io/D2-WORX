# 0020 — Resilience ownership + pipeline completion

> Gitignored workspace. Deliverable snapshot lands at `docs/dev/deliverables/0020-resilience-ownership.md` at SHIP.

## Goal

Make `D2.Shared.Resilience` (+ the TS `@d2/resilience` parity lib) the **sole, feature-complete** resilience mechanism — network **and** value — and **remove the BCL `Microsoft.Extensions.Http.Resilience` `AddStandardResilienceHandler()` globally** from ServiceDefaults. Resilience is caller/client-side, **opt-in** (off by default — it costs latency), and **per-call overridable** (an endpoint may declare a default pipeline; a caller uses it, supplies its own, or bypasses). Idempotency + everything else stay server/provider-side. Prerequisite for the 0019 Step-9b gRPC-client emitter.

## Locked decisions

- **The pipeline becomes complete + sole.** Add `TimeoutLayer` (total + per-attempt) + `RateLimiterLayer` (concurrency) as native `IResilientLayer` impls; no BCL handler anywhere.
- **RateLimiter = hand-rolled `SemaphoreSlim`** (O-1) — ~30 LOC; matches the <500-LOC / sole-external-dep ethos; NOT `System.Threading.RateLimiting`.
- **Concurrency limiter now; token-bucket deferred** (O-3) as a trivial future layer.
- **Mappings**: timeout → `ServiceUnavailable` (503, transient-retryable — `TimeoutException` is already classified transient by `RetryHelper.IsTransientException:74`, so a per-attempt timeout retries with zero classifier edit); rate-limit rejection → `TooManyRequests` (429 / `RATE_LIMITED` — generic factory verified at `D2Result.Generic.Factories.g.cs:181`).
- **Canonical order**: `RateLimiter → TotalTimeout → Retry → CircuitBreaker → PerAttemptTimeout`; Singleflight outermost when used (O-9).
- **`ResilientPipeline.PassThrough` sentinel** (O-8) — zero-layer pipeline for the per-call bypass override.
- **Caller-side opt-in + per-call-override convention** documented — additive to the existing lib-internal-invisible pattern (NOT a replacement of it).
- **Migrate existing consumers in this step** (O-6) — `key-custodian-client.ts` setTimeout/abort + BCL-reliant auth HttpClients onto the new layers.
- **ADR-0013 + ADR-0014 amended in-place** (O-5; per the "ADRs reflect current truth" convention). ADR-0014 inverts from "in-process gap-filler beside the BCL handler, not a replacement" → "sole, complete, opt-in, caller-side mechanism."
- **Cross-language parity** (ADR-0014): the new layers ship in **both** C# and TS.

## Candidate predicates for rules.md

All three distilled from the 0020 audit-loop — APPLIED to `docs/dev/rules.md` post-SHIP.

1. **Baseline-dismissal validity** — a "pre-existing / baseline / flaky" dismissal of a failing test is only valid when the cited item EXISTED on the branch's base commit before any current-deliverable change was applied. New code (introduced by the current deliverable) can never have a pre-existing failure. Orchestrator must git-verify (`git show <base>:<file>`) before accepting any dismissal. — **APPLIED as §24.25** (0020 evidence: two Fixers dismissed failing RateLimiter tests as "pre-existing baseline flaky"; impossible — the resilience lib was entirely new since the baseline commit; the failures were two real bugs in the new code.)

2. **Closure-by-absence requires the artifact to exist** — concluding "clean / closed" from zero grep hits on a report path (TRX, inspectcode log, test results XML) is only valid after confirming the artifact FILE EXISTS (existence check + non-empty confirmation). An empty grep on a missing or never-written path is a FALSE-CLEAN. — **APPLIED as §24.26** (0020 evidence: an orchestrator verification run's `--report-trx` file was never written due to a path/invocation error; greps on the missing path returned empty and almost read as "all tests passed.")

3. **The inspectcode gate is SOLUTION-scoped** — `jb inspectcode server/D2.slnx` is the only valid gate command. A per-project run (`jb inspectcode <one>.csproj`) UNDER-COVERS (never inspects the test project) AND produces FALSE POSITIVES (can't resolve `<ProjectReference>` types → spurious "unused using" findings). Both failure modes were realized in 0020: 12 genuine test-file findings accumulated invisibly across Stages A/C because per-project scope was used; two Fixers over-claimed those false-positive using findings as "safe to leave," and the canonical solution-scoped run revealed both the real test-file findings and the absence of false positives. — **APPLIED as §24.21 EXTENSION** (refined the existing §24.21 predicate — added the false-positive failure mode rationale and strengthened the closure-invalidity statement; did not create a duplicate predicate).
