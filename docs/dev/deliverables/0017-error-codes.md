# Deliverable 0017 — Unified spec-driven error-code + TK system

**Status:** SHIP — converged + governed; squashing into `n/keycustodian` · **Branch:** `n/error-codes` (off `n/keycustodian` @ `e028b16e`) · **Research:** `docs/wip/error-codes-research/SYNTHESIS.md`

## Goal
One spec-driven way to declare every error code in the system — OOTB or domain-specific — pairing each code with its `httpStatus`, `category`, and **translation key (`userMessageKey`)**, generating .NET + TS constants + typed `D2Result` factories from the spec, so **any service can resolve the code + localized message for anything it consumes** (branch on the code, render the TK), and services can consume each other's *custom* errors or use OOTB codes where it makes sense. Generalizes the existing **auth-error-codes** pattern (the only catalog that already links code↔TK) into the project-wide convention. Unblocks the KeyCustodian (0016) domain retrofit.

## Why now (the forcing function)
KeyCustodian's domain transitions need to fail with KC-specific, cross-service-resolvable codes. The current `D2Result` error layer has the code↔TK link buried in C# factory bodies (the generic `error-codes.spec.json` carries no `userMessageKey`), three disconnected catalogs (generic / auth / DB), unvalidated free-text custom codes, and no way to resolve a message from a code alone. Building this right *before* KC (and auth, and every later service) consumes it avoids a half-baked precedent. User: "do this right, right now."

## Locked decisions
> _Decisions 1-16 below incorporate the 2026-06-06 design discussion (captured in `## Living State`)._

1. **Topology = per-domain specs + a reserved generic catalog.** Keep `contracts/error-codes/error-codes.spec.json` for cross-cutting D2Result status codes; each domain that needs specific codes gets its own `contracts/<domain>-error-codes/<domain>-error-codes.spec.json` (generalizing `auth-error-codes.spec.json`).
2. **Canonical spec schema — 7 fields:** `code` (SCREAMING_SNAKE, unique; **domain-prefix-enforced** per dec. 4) · `httpStatus` · `category` (closed semantic enum) · `userMessageKey` (TK ref) · `factoryName` · **`factoryShape`** (closed enum that drives the generated factory's *signature* — must cover every current D2Result factory variant so regeneration is byte-identical) · `doc`.
3. **`category` = semantic/telemetry tag AND a wire field — NOT the factory selector.** **`httpStatus` selects the base D2Result factory** (401→`Unauthorized`, 409→`Conflict`, 400→`ValidationFailed`, …; deterministic; preserves auth byte-parity). `category` is added to the **wire** (gRPC trailers + JSON envelope) so a consumer can do generic class-based handling ("retry any `infrastructure_unavailable`") **without importing the producer's catalog**.
4. **Code uniqueness = enforced domain prefix.** The generator derives the domain token from the catalog filename (`<domain>-error-codes.spec.json`) and **requires every code to be `<DOMAIN>_*`**; the generic catalog owns the sole **reserved unprefixed namespace** (`NOT_FOUND`, `CONFLICT`, …); the merged-registry build (dec. 9) **hard-fails on any cross-catalog code collision** (backstop). Prefix-as-namespace makes collisions structurally impossible + wire codes self-describing.
5. **Generate the generic D2Result semantic *failure* factories + per-code booleans from the generic spec** — `NotFound`/`Forbidden`/`Unauthorized`/`ValidationFailed`/`Conflict`/`ServiceUnavailable`/`UnhandledException`/`PayloadTooLarge`/`TooManyRequests`/`Canceled` + `IsNotFound`/`IsConflict`/… — with the signature driven by `factoryShape`. **PRESERVE hand-rolled (not code-derived):** `Ok`/`Created`/`Fail`; `Bubble`/`BubbleFail`; `Combine` (+helpers); monadic `Bind`/`Map`/`Match`; the `SomeFound`/`PartialSuccess` *factories* (data-carrying — only their code/status/boolean are spec-derived); composite booleans `IsPartialOrMissing`/`IsTransientRetryable`; guard/async extensions; the core type/ctor/props/wire-envelope/`Unit`. **Byte-parity gated** (D2Result is the spine — highest blast radius in the deliverable).
6. **One generalized generator** per runtime, run per `*-error-codes.spec.json`, deriving the emitted class names (`<Domain>ErrorCodes`/`<Domain>Failures`) + the enforced domain prefix from the spec. Unifies the two current near-identical stacks (generic + auth). Adding a catalog = drop a spec + register it; no new generator.
7. **Domain catalogs generate BOTH `<Domain>Failures` (→ `D2Result`) AND `<Domain>Failures<T>` (→ `D2Result<T>`)** factory classes (identical method names), each delegating to the `httpStatus`-selected base factory, stamping the domain `code` (via the base factory's `errorCode` override) + `userMessageKey`. **Framework/common codes stay on `D2Result` / `D2Result<T>` directly** (the constructing mode, dec. 5). **The rule:** `D2Result.X()` = framework-universal codes; `<Domain>Failures(.<T>).X()` = domain-specific codes — the call site names the scope, mirroring the `D2Result`/`D2Result<T>` split. *(API-consistency decision, user-ratified 2026-06-07: resolves the "domain failures from a class vs common failures from the type, and no typed domain variant" seam. **Reaches back into committed Step-1 auth** to add `AuthFailures<T>` — additive; existing `AuthFailures` + `AuthErrorCodes.g.cs` stay byte-identical, the generic twin is new.)*
8. **Selective import + registry at the boundaries.** Services import ONLY the catalogs whose specific codes they handle (branch on `<Domain>ErrorCodes.*`); generic handling uses the wire `category`; the **merged registry serves the central boundaries** (Edge/BFF) that must resolve/render *any* code.
9. **Merged registry (both runtimes)** — generated `code → {httpStatus, userMessageKey, category, domain}` across all specs + a resolution API + the global code-collision check (dec. 4 backstop).
10. **Readable gRPC trailers** — reconstruct a `D2Result` (code + TKs + inputErrors + trace + **category**) at the *consuming* service (today write-only).
11. **TK-validity enforcement (user requirement).** (a) generator build-time **diagnostic/error** if a `userMessageKey` doesn't resolve to a real TK (cross-check target = `contracts/messages/en-US.json`, via the inverse `KeyDecomposer` transform — NOT the generated `TK.g.cs`, which would be circular); (b) a **cross-runtime test** asserting every spec's `userMessageKey` resolves + *renders* (not the raw key) in both runtimes.
12. **Generic-spec backfill** — add `userMessageKey`/`category`/`factoryShape` to the 15 generic codes; fix the orphan `IDEMPOTENCY_IN_FLIGHT` TK + reconcile the stale Paraglide `CANCELLED`→`CANCELED` drift.
13. **`factoryName` stays explicit in the spec** (matches auth; auto-derive-with-override considered + deferred — not worth the generator complexity now).
14. **Schema file = one canonical shared schema** at `contracts/error-codes/error-codes.canonical.schema.json` (draft-07), beside the generic catalog; the generic + auth + future per-domain `schema.json` files conform to / reference it (exact `$ref`-vs-generated-copy mechanism settled when the first consumer is retrofitted, Step 1/3). *(User decision at the Step-0 review gate, 2026-06-06: placed inside `contracts/error-codes/` rather than a standalone schema-only dir.)*
15. **Branch + ship.** 0017 on `n/error-codes` → merges back into `n/keycustodian` (linear). Both 0016 + 0017 squash-merge to nova together as one merge. ADR + rules.md (§26 codegen + §5.3 factories: no free-text codes; every code spec-declared with a valid `userMessageKey`) + PATTERNS.md at ship.
16. **Out of scope:** KeyCustodian's own `keycustodian-error-codes.spec.json` + the KC transition retrofit (KC's resume work — the first *new* consumer). DB-codes catalog migration to a spec deferred unless trivially folded.
