# D2.Audit

> **Status**: placeholder — not yet implemented.

## Purpose

Append-only audit store. Consumes `d2.audit.events` from RabbitMQ (encrypted); writes to `audit_db` with INSERT-only role. Different retention + access control from operational data.

Every service publishes `AuditEvent` to the `d2.audit.events` exchange (fanout, fire-and-forget). D2.Audit consumes, decrypts, persists. **Telemetry stays clean** — OTel spans carry only correlation IDs, never the audit payload itself.

## Why a separate service

- Different retention policy from operational data (audit retained for years; operational data weeks/months)
- Different access control (compliance / legal can be granted read-only without touching anything else)
- Append-only easier to enforce in dedicated DB (revoke `UPDATE` / `DELETE` from the service role; only `INSERT` allowed)
- Cross-service audit (Edge actions, Files actions, Courier actions) all flow into one query surface
- Optional later upgrade to tamper-evident immutable bucket (S3 Object Lock) without changing producers

## Public API surface

- gRPC: read-only query endpoints for compliance / support / admin lookups
- RabbitMQ consumer: subscribes to `d2.audit.events` fanout exchange
- REST API (TBD): admin UI integration for searchable audit log

## Dependencies (.NET shared libs)

- `D2.Shared.Auth` (admin-org gate on read endpoints)
- `D2.Shared.Encryption` (decrypts audit payloads from RMQ)
- `D2.Shared.Messaging` (consumer for `d2.audit.events`)
- `D2.Shared.Handler`, `D2.Shared.Result`, `D2.Shared.Utilities` (foundational)

## Database

- `audit_db` — owned by D2.Audit. Service role has INSERT-only on `audit_event` table (no UPDATE / DELETE granted). Schema: `audit_event` (id, event_type, actor user/org, actee user/org, action, resource type/id, metadata JSONB, source IP, fingerprint, correlation ID, created_at) + `support_session` (denormalized impersonation start/end rows) + `incident` (auto-generated by KeyCustodian compromise events).
- On the same PG server
